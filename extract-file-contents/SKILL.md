# Extract File Contents

指定されたファイルの内容を読み取り、検索・引用・再利用可能なテキストとして展開する。要約ではなく、原文の忠実な抽出と構造保持を優先する。

## Procedure

1. 対象ファイルを特定する。
  - ユーザーが指定・選択・言及したファイルを対象にする。
  - 対象が曖昧で、複数候補がある場合は確認する。
  - 元のファイルを削除・移動・置換しない。
2. ファイルを取得する。
  - ファイル名、拡張子、読み取り可否を確認する。
  - 権限エラーになる場合は、同じファイルをスレッドに再添付してもらい、取得可能な参照から処理する。
  - 利用可能なファイル取得・文書処理手段を使い、取得できない内部参照を推測で組み立てない。
  - パスワード保護、破損、未対応形式などで読めない場合は推測せず、その状態を記録する。
3. 内容を抽出する。
  - DOCX：見出し、段落、箇条書き、表の順序を保持する。
  - PPTX：slideごとに、番号、タイトル、本文、表、speaker notesを分ける。
  - XLSX / CSV / TSV：sheet名、列見出し、使用範囲内の値、数式が重要な場合は表示値と数式を保持する。
  - PDF：pageごとに、見出し、本文、表を保持する。スキャンPDFはOCR結果であることを明記する。
  - TXT / Markdown：原文構造を維持する。
4. 必要な場合だけ英訳版を追加する。
  - 抽出原文が主に日本語で、対訳版が有用な場合は、原文抽出後に `#### English translation` を置く。
  - 英訳は[翻訳規範](..# local content excludedtranslation-rules.md)の用途Bに従い、原文構造を保持する。
5. 指定先へ配置する。
  - `Extracted text: <ファイル名>` を見出しとして配置する。
  - 既存の同名セクションがある場合は更新し、重複セクションを作らない。
  - 大容量の場合は、slide、sheet、page、section単位に分ける。

## Output

- 指定文書がある場合はそこへ記載し、ない場合はチャットへ出力する。
- 抽出内容の冒頭に、AI抽出であり抽出漏れ・レイアウト解釈・OCR誤認識等があり得る旨の注意書きを置く。
- チャットには、処理したファイル、配置先、未展開範囲、読み取り不能箇所だけを短く報告する。

## Hard constraints

- ファイル内容を勝手に要約、増減、正規化しない。
- 抽出不能箇所を推測で埋めない。
- 大容量ファイルで未展開範囲を黙って省略しない。
- 複数ファイルの内容を1つのセクションへ混在させない。
- 抽出テキストを正式な原本や最新版として扱わない。
- 資料に記載された想定・候補・fallbackを、会議で決定された内容として書き換えない。
- 変更範囲、原意・事実保持、構造保持は[編集ガードレール](..# local content excludedediting-guardrails.md)に従う。
