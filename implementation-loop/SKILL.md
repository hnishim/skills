# Implementation Loop

承認済みPlanを唯一の基準とします。Planの範囲を広げず、実装前に必要な検証と停止条件を決めます。レビューは共通機構を使い、厳格さだけをプロファイルで変えます。

## ルーティング

- Planがない、曖昧、検討中、または明示的に承認されていない場合は使用せず停止します。Planの作成・拡張・再解釈・承認はこのスキル内で行いません
- 承認済みPlanがあり、単一ユーザー向けのローカルスクリプトで、共有サービス・本番データ・機密情報・権限変更・不可逆な外部副作用がなく、「厳格」「レビュー」「テスト先行」「独立レビュー」「本番」「共有」「公開」「セキュリティ」等の指定もない場合は軽量プロファイルを使います
- それ以外は厳格プロファイルです。実行前に [references/strict-profile.md](references/strict-profile.md) を読みます

## 軽量プロファイル

1. Plan、変更対象、関連指示だけを確認します。要件のない抽象化、設定化、依存関係、リファクタリングは追加しません
2. 親Agentが必要なファイルだけを最小限変更します。行数・ファイル数を増やす場合はPlan上の理由を確認します
3. 利用可能な構文・型・静的チェックと、代表的な成功経路を実行します。小さな構文変更は構文チェックだけで終了できます。失敗経路、fixture、専用ヘルパー、テストスイートはPlanまたは実リスクに必要な場合だけ追加します
4. 差分、実行結果、未検証事項を確認します。共通レビューを1回行い、Plan内の指摘だけを修正して関連チェックを再実行します。再レビューは1回までです
5. テスト専用ゲート、受入・リスクマトリクス、複数回のレビューサイクルは追加しません。共有・本番・外部副作用・機密情報・権限・データ損失のリスクが判明した場合は厳格プロファイルへ切り替えるか、ユーザー判断を求めて停止します

## 共通レビュー

- 独立したreviewerに、承認済みPlan、範囲、関連指示、差分、テスト結果、未検証事項を渡します。正確性、Plan適合、範囲、回帰、エラー処理、セキュリティ・プライバシー、規約を根拠付きで確認させ、提案や好みはブロッカーにしません
- 軽量プロファイルは最終差分を1回レビューします。CHANGES_REQUIREDならPlan内の修正と関連チェックを行い、同じreviewerに1回だけ再確認させます。解決できない、またはPlan外の判断が必要なら停止して報告します
- 厳格プロファイルは、テスト専用ゲートと実装レビューをreferences/strict-profile.mdの手順で行います

## 共通の安全策

- 無関係な既存変更を保持します。Planが明示的に許可しない限り、リセット、破棄、上書き、ステージ、コミット、プッシュ、PR作成、外部システムへの書き込み、\破壊的操作をしません
- 権限不足、継続するテスト環境の失敗、指示の衝突、Planからの重大な逸脱があれば停止します
- 厳格プロファイルでは、実効エージェント、モデル、推論設定、テスト結果、未検証事項を記録します。REVIEW_LIMIT_REACHEDは不完全であり、成功扱いにしません

厳格プロファイルのエージェント契約、テスト専用ゲート、レビュー回数、完了・非PASS報告の形式は [references/strict-profile.md](references/strict-profile.md) に従います。
